These are free tools and references for Starfield players and modders: console commands, item and place IDs, game settings, globals and quests, the record types behind every plugin, every game version, how Starfield modding is doing on Nexus Mods and how much it is played on Xbox. Modding tools

These free, open-source programs help mod authors check, build and explore Starfield mods. The checkers and the Voice Tool only read your files, and none of the tools makes network connections.

sf-mod-check

It checks a Starfield plugin (.esm) for problems that break it in the game: broken links, FormIDs out of range, bad headers, scenes, conditions, deleted and identical-to-master records. After each kind of problem it says how to fix it in xEdit or the Creation Kit. Its release command checks a finished mod zip before you upload it, and its triage command looks over a mod you downloaded, offline, and lists what is worth a look. It was called sfmodcheck until 0.8.0.

Drop your plugin on sf-mod-check.exe before you play, run sf-mod-check release on your zip before you upload it, and run sf-mod-check triage on a mod you downloaded before you install it.

papyrus-log-check

It reads a Starfield Papyrus log and checks it against a rule file for your mod, so each expected log line is reported as PASS, FAIL or NOT SEEN.

Check after a test session that your mod's scripts did what they should.

BuildKit

It is a C# library for writing Starfield plugins with Mutagen 0.54.4: it finds the masters, writes plugins the way the Creation Kit does (overridden-forms list, effect data, one thread) and keeps FormIDs stable between builds.

Build your mod's plugin from code instead of by hand.

sfcutcheck

It finds what Starfield never uses: cut weapons, quests nothing starts, dialogue nobody says and items in lists nothing hands out. For each one it shows the chain of records behind the answer. Mod authors can also point it at their own plugin to find records the mod adds but never uses.

Run a scan to see the cut content, or check your own plugin for leftovers.

Windows exereads only

version 0.1.8 · released 2026-11-16 · download

sf-pex-tools

It tells you whether two compiled Papyrus scripts do the same thing even when their bytes differ, which is always true after a rebuild, and it lists, extracts and compares the files inside .ba2 archives. It can compare the scripts in two archives in one command.

Check that a rebuild of your mod changed only what you meant to, or pull one file out of an archive.

Python 3.9+reads onlyMIT

version 0.1.0 · released 2026-11-18 · download

sf-log-collector

It gathers the logs a mod author asks for after a bug into one zip with a double-click: Papyrus, SFSE and crash logs, your INIs, plugins.txt, mod settings, new screenshots and Windows crash events, plus saves if you ask. Each run picks up only what changed since the last one. It works with Steam, Game Pass, Vortex and Mod Organizer 2.

Quit the game after the bug, double-click the collector and attach the zip to your bug report.

sf-mod-build

It builds a Starfield mod from one project file, sfmod.json, with one command. It compiles the mod's Papyrus scripts with your Creation Kit's compiler (never with -release, so the logging stays), runs the mod's Mutagen builder to write the plugin, packs the scripts into a BA2 with Archive2, writes a zip that gives the same bytes every time and runs the sf-mod-check release check on it. A dotnet new template makes a starter mod that builds as is.

Make a starter mod with dotnet new sfmod, then run sf-mod-build build in its folder.

sf-load-order

It checks your Starfield load order before you play. It reads the game's Plugins.txt, a Mod Organizer 2 profile or a file exported from Vortex's Load Order page, and reports masters in the wrong order, missing files, patches built for an older version of a mod, known clashes from your LOOT masterlist, and archive and loose-file overlap. With sf-mod-check installed it also finds record conflicts. Then it suggests a better order and writes plugins.txt, MO2's loadorder.txt and a file for Vortex's Import button.

Unzip the release and run sf-load-order.cmd in that folder, then open the report.html it writes.

sf-save-reader

It reads a Starfield save (.sfs) and shows what is in it: the character, the game version, every plugin the save depends on, and the state of every quest (running or stopped, current stage, stages done and objectives). Point it at your Data folder and it names the quests from the game's plugins and your mods. It can also list a mod's change records, compare two saves and hide the player name for bug reports.

Run sf-save-reader quests on a save with --data to see where each quest stands, or dump to see the plugins the save needs.

sf-test-plan

It turns a Markdown test plan for your mod into one offline checklist page. Testers mark each step Pass, Fail or Skip with a note while they play, and the page keeps the marks in the browser and exports them as JSON. It can add those results to a file next to the plan and turn a papyrus-log-check report into marks for the steps the log proves.

Write a plan with sf-test-plan new, build the page with sf-test-plan build, and open it in your browser while you test.

Starfield Voice Tool

Find a companion's lines, check what a mod's voice files say, or get audio clips for a mod or video.

SquareSnap

It takes square screenshots on Windows, in WSL and on Linux: you drag over part of the screen, it keeps the selection square, shows a preview and saves it as a PNG.

It opens and searches text files of many gigabytes, such as logs and dumps, in seconds, and can follow a log while a program is still writing it. It never changes the file.

About

  • Each site is a single page that works in any browser, on a phone too, with search built in. There's no sign-up, no ads and no tracking.
  • The lists are read from the Steam copy of the game and rebuilt after game updates; each card shows the game version it was built from.
  • The tools are open source (GPL-3.0 or MIT). Each tool's card shows its latest version and links to its download page; the newer releases list a SHA-256 checksum for every file. Each tool's README on GitHub says how to install and use it.
